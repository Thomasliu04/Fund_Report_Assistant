本文分两部分：**(A) 需求文档**（当初要解决什么）与 **(B) 维护文档**（代码各模块做什么、改哪里）。

# A. 需求文档

## 1. 背景与目标

公募规模简报（季度 / 半年度）数据日当天工作量大：底稿 Excel 已有终表与排名，但 PPT 仍需手抄数字、贴表图，易错且费时。

**目标：** 做一套本地辅助工具，从「Part 1 底稿」生成：

1. **表图 Excel**（带数据条 / 色阶 / 银华高亮）——主产物，人工微调后贴进 PPT  
2. **PPT 文字初稿**——数字从终表读出自动成文；表图默认不自动贴（Mac 难稳定出案例级 WMF/EMF）

原则：**数字以底稿终表为准**，避免 CSV 与 Excel 双算不一致。

## 2. 核心需求清单（按提出顺序归纳）

| # | 需求 | 接受标准（摘要） |
|---|------|------------------|
| R1 | 读底稿终表，导出样式对齐案例的表图工作簿 | 10 页 sheet；蓝条/红条/色阶；银华高亮 |
| R2 | 生成全册 PPT 叙事文字 | 对齐 Q4 案例句式；银华排名/增速与终表一致 |
| R3 | 网页操作台 | 上传 → 确认期别日期 → 生成 → 下载 PPT/Excel |
| R4 | 底稿健全性检查 | 缺 sheet、增速刻度混用等要报 error；网页有 error 禁止生成 |
| R5 | 默认不自动贴表图 | 清掉模版旧表图，放粘贴占位；提供 sheet→页粘贴清单 |
| R6 | 文字必须从本期 `tables.xlsx` 读数 | 禁止与 CSV 双路径导致数字漂移 |
| R7 | H1 措辞正确 | 用「上半年 / 26H1」，勿误写成「全年」 |
| R8 | 期别适配 Q1 / Q3 / Q4 / H1 | 见下节三种叙事模式 |
| R9 | 可迁移到 Windows | 主流程跨平台；Excel 静默导出可为 Mac 可选 |
| R10 | 文档可在网页内查看 | 出报指引 / README 侧栏拉窗 |

## 3. 期别叙事口径（R8 细化）

| 模式 | 典型期别 | 主口径 | 辅口径 |
|------|----------|--------|--------|
| `single_quarter` | Q1 | 仅单季（YTD≡季度） | 无第二套排名话术 |
| `quarter_lead` | Q3 | 单季（Q3） | 前三季度 / YTD 并列 |
| `period_lead` | H1、Q2、Q4 | 半年度或全年 | 单季为附带 |

行业表日期：常规 3 列 `YYYYMMDD`（期末→上季末→年初）；**Q1 可仅 2 列**（期末→年初）。

## 4. 非目标（明确不做 / 延后）

- 不为 Q1/Q3 单独做 PPT 模版（统一 Q4 版式 + 手贴表）  
- 不 100% 复刻每期底稿物理列顺序（读数靠**列名**，不是靠列号）  
- 不依赖打包 exe 才能用（源码 + venv / 网页台即可）  
- Notebook / 数据库直连非当前主路径  

## 5. 推荐使用方式

```bash
python main.py serve --open
```

上传底稿 → 确认期别与三个日期 → 生成 → 下载 Excel/PPT → 按粘贴清单贴表 → 人工改观点句。

# B. 维护文档

## 1. 端到端数据流

```text
底稿.xlsx
  ├─ validate_draft     结构/增速刻度检查
  ├─ normalize_draft    sheet 改名、Top30、表头别名
  ├─ load_final_tables  → 内存中的 (sheet名, ColumnSpec, rows)
  ├─ deck_workbook      → output/{期}_tables.xlsx   【主产物】
  └─ table_facts + sheet_narratives
        → 填入 25Q4_template.pptx（只文字，清旧图）
        → output/{期}_briefing.pptx
```

网页路径：`briefing/web/app.py` 上传到 `data/_web_jobs/job_*`，生成时调用 `full_deck.run_full_deck(..., paste_tables=False, strict=True)`。

| 路径 | 职责 |

## 3. 各模块「具体做了什么」

### 3.1 期别 `period_profile.py`

`resolve_period_profile(label, period_type, current_date)`：

- H1/H2 → `period_lead`，ytd=`26H1`，span=上/下半年  
- Q1 → `single_quarter`，只出单季话术  
- Q3 → `quarter_lead`，ytd=`前三季度`，主句先 Q3  
- Q4 → `period_lead`，ytd=`{yy}年`，span=全年  
- 4–6 月无标签 → 猜 `H1`  

网页 `_write_config` 用 Profile 写 `column_labels`，保证终表表头前缀与文字一致。

### 3.2 校验 `validate_draft.py`

检查：10 页 sheet 是否齐全、行业日期列数量（≥2）、品类行、公司列、增速列是否混用 0.02 与 2、ETF 右表定位等。  
**error** → 网页禁止生成；CLI `export-tables` 默认中止（`--force` 可跳过）。

### 3.3 规范化 `normalize_draft.py`

统一 sheet 名、截 Top30、ETF 双表列位、把 `YTD*`/`季度*` 改成 Profile 标签（如 `前三季度增速`、`Q3增量`）。**不重算**规模数字。

### 3.4 终表导出 `final_tables.py` + `deck_workbook.py`

- 按 sheet 别名找到源表，读第 1 行表头，**保持相对列顺序**写出  
- `_column_spec` 根据**表头文字**决定：蓝条 / 红双向条 / 排名色阶 / 百分比格式  
- 「使用说明」页含 **终表 sheet → PPT 页** 粘贴清单（ETF：左非货含联接、右权益含联接）

### 3.5 读表成文 `table_facts.py` → `sheet_narratives.py`

1. 每个 sheet 用 `_map_role_indices` 把列名映射到角色：`aum` / `increment` / `growth_pct` / `q_*` / `rank_change` …  
2. 增速按列中位数判断「百分数 vs Excel 小数」  
3. `sheet_narratives` 按 `PeriodMode` 生成 overview / total / non_money / increment / 业务页句子  
4. `full_deck` **始终从写出的 tables.xlsx 再读一遍** 成文（`narrative_source=tables`）

### 3.6 PPT `full_deck.py` + `pptx_filler.py` + `slide_map_q4.yaml`

- 复制模版 → 按 map 替换指定 shape 的段落  
- `paste_tables=False`：删除 picture shape，加「请从本期 tables.xlsx 粘贴」占位  
- `--paste-tables` 才走 Excel/PIL 出 PNG（Mac AppleScript 路径，Windows 通常跳过）

### 3.7 网页 `web/app.py`

上传校验缓存 `draft_validation.yaml`；生成前 `_require_draft_ok`；预览银华关键指标优先读终表。

## 5. 列的顺序对结果有没有影响？

### 结论（先看这个）

| 场景 | 列顺序有影响吗？ |
|------|------------------|
| **PPT 文字读数**（`table_facts`） | **基本按列名，不按列号**。同名角色列有多列时，取**从左到右第一个**匹配项 |
| **行业表三个日期列** | **有影响**：约定顺序为 期末 → 上季末 → 年初；只认位置上的前 2/3 个 `YYYYMMDD` |
| **tables.xlsx 展示** | **有影响（观感）**：导出大致保留底稿列序；条件格式按列名特征上样式，不依赖绝对列号 |
| **空表头** | **有影响**：空表头会截断后续列（校验会报） |
| **ETF 左右表** | **有影响**：右表靠表头含「权益ETF」+「排名」定位起点，不是写死列号，但左表默认前若干列 |

### 详细说明

1. **角色映射是「名驱动」**  
   例如找 YTD 增速：找表头含「增速/增幅」且**不是**单季标签（`Q3*` / `季度*`），且识别「前三季度」为 YTD 窗口而非单季。  
   因此把「前三季度增速」整列挪到最右侧，**只要列名不变，文字数字不变**。

2. **同角色多列时「先匹配者胜」**  
   `_pick_col` 从左扫到右。若误放两列都像「增量」且都不是单季，会吃到左边那列——这是顺序敏感点。维护时避免重复语义列，或保证正确列在左侧/表头足够具体（如带 `非货增量`、`前三季度`）。

3. **日期列是少数「位置约定」**  
   - 3 列：第 1 个日期=期末规模，第 2=上季，第 3=年初  
   - Q1 仅 2 列：期末、年初（上季末回退为年初）  
   调换期末与年初列会导致规模/增速口径错乱。

4. **增量表特例（Q3）**  
   Q3 的 `4非货增量` 往往只有「季度非货*」列。系统会：单季从该表读；YTD 增量/排名从 `03_非货` 补。此时列序不如「有没有 YTD 列」重要。

5. **实践建议**  
   - 改底稿时优先改**表头文字**与**日期列顺序**，不要依赖「第 5 列一定是增速」  
   - 不要留空表头打断列  
   - 增速一列内不要混用 `0.02` 与 `2`  
   - 对外分发前跑 `validate-draft`，看 error 再生成  

## 6. 常见故障

| 现象 | 可能原因 |
|------|----------|
| PPT 仍像旧稿 | 未重启 `serve`；下到旧文件；或只看了模版残留表图（现已清空） |
| 开篇「本页数据不足」 | 行业表无「期末」/日期列，`aum` 未解析到 |
| Q3 写成「全年」 | 旧代码；确认已用 `period_profile` 且 label 为 `25Q3` |
| 增速 100%/200% | 同列混用百分数与小数 |
| 网页不能生成 | 上传校验有 error，需改底稿重传 |
| 银华找不到 | 公司名不含「银华」；或该 sheet Top30 外（少见） |
